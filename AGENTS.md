# Project Architecture & Guidelines — Gem Vanguard (Poki Match-3 Battler)

## Mandatory Workflow Rule
- **После каждого завершения работы агент обязан сделать коммит в ветку `main`.**

## Core Principles
1. **Target platform**: Poki (`wasm-web`). Fast startup, compact release bundle, portrait (mobile) and landscape (desktop).
2. **Visual Style**: Casual Dark Fantasy — deep indigo/slate stone (`#111521`, `#1c2233`, `#262e45`), aged gold/bronze accents (`#e8b84b`), saturated elemental gems (`red`, `yellow`, `purple`, `green`, `blue`), expressive commander face portraits, and squad sprites of **1–5 warriors**.
3. **GUI only & Zero Heavy Physics**: Everything is rendered via `main/gui/game.gui` with code-built nodes and lightweight GUI tweens. `main/game.appmanifest` strips Box2D/Bullet/models/particles.
4. **Druid UI**: All interactive GUI goes through [Druid](https://github.com/Insality/druid) 1.3 (dependency together with `defold-event`):
   - `ui.lua` owns two Druid instances — the `screen` layer and the `popup` layer (`ui.open_layer` / `ui.close_layer`). Input is routed to the popup layer while a popup is open.
   - Buttons (`ui.btn`, `ui.button`), auto-fitting texts (`ui.label`), progress bars with damage "ghost" (`ui.bar`), stencil scrolls (`ui.scroll`), popup blockers and back handlers, and the board drag (`new_drag`, used for swaps AND for blast taps) are Druid components. Style lives in `main/gui/druid_style.lua`.
   - Button callbacks are deferred one frame (`ui.defer`) because Druid animates the node after the callback and callbacks often rebuild the screen.
   - Always call `druid:final()` (via `ui.close_layer`) **before** deleting the nodes of a layer. `druid.no_auto_input = 1`: the gui_script owns input focus.
   - `druid:final()` does not cancel Druid's `late_init` timer (`timer.delay(0)`); `ui.close_layer` cancels it, otherwise a layer opened and closed in the same frame crashes with "Deleted node". To rebuild the screen under a new popup use `app.refresh_then_popup(kind, data)` (never `open_popup` + `rebuild`).
   - Nodes that are deleted outside of a layer close (HUD pieces, tutorial pills, FX) must not own Druid components: use `ui.text` / `ui.label(..., { plain = true })`.
   - Input coordinates are converted to the virtual canvas once in `game.gui_script` (`action.x/y`), so `gui.pick_node` works with `ADJUST_REFERENCE_DISABLED`; drag uses `NO_USE_SCREEN_KOEF`.
5. **Virtual canvas**: `main/modules/layout.lua` maps the window to `720x1280` (portrait, aspect < 0.9) or `1600x900` (landscape); the extra dimension grows with the screen. Layouts are computed from the real `app.vw/app.vh` and centred composition widths, never from fixed pixel positions.
   - Battle portrait: top bar (pause, stage + opponent, round) -> arena with 3 lanes (your squad vs the enemy squad of the same gem colour) -> turn bar (portraits, team HP + shield bars, moves, YOUR TURN / ENEMY TURN pill) -> 7x7 board -> boosters. Landscape: left column (top bar, arena, turn bar, boosters), board on the right.
   - HP is one pool per side (commander). Squads are visual: every attack / skill flies from the striking squad into the enemy squad of its lane; the losing army falls at the end. Turn changes: sweeping ribbon banner, red veil over the board on the enemy turn, golden halo + glowing ground under the active side, enemy moves telegraphed by a red claw.
   - Squads tab (Clash Royale style): battle squad (3 big cards + moves-per-turn row), collection, cards not found yet; a card popup shows stats with the next-level gain.
   - Hub: top bar (commander, league, gold, gems, settings) + bottom tab bar (Shop, Squads, Battle, Tower, Map, Quests) with notification badges. Tabs unlock progressively by wins: Battle/Squads after the 3 onboarding fights, Tower at 4, Map/Quests at 5, Shop/PvP/Trial at 6 (`progress.tab_unlocked`).
6. **Modular Architecture**: Keep code split into small single-purpose modules:
   - Logic (`main/modules/`): `config`, `squads`, `campaign`, `board`, `ai`, `battle`, `progress`, `quests`, `i18n`, `layout`, `rng`, `poki`, `audio`. Core combat / board / economy logic has zero Defold API calls (except `sys.save/load`) so it runs headlessly in simulations.
   - Views (`main/gui/`): `ui`, `druid_style`, `widgets`, `battle_view`, `hub_view` (shell + home tab), `cards_view`, `map_view`, `shop_view`, `quests_view`, `popups`, `game.gui_script` (app controller, popup queue, navigation).
7. **Determinism**: Gameplay RNG uses `rng.lua` (Park-Miller); `math.random` is only for visual FX.
8. **Rebuildable views**: Resize/orientation rebuilds screens via `app.rebuild()`. Delayed callbacks use `ui.after(...)` (generation-guarded, restores the Druid layer).
9. **Battle animation contract**: `battle.lua` tags every effect event with the cascade `step` it came from; `battle_view.process()` animates each step (clear -> specials -> gravity -> refill) and schedules effects at their step time, then `sync_board()` reconciles with the logic grid.
10. **Balance & core loop**: `config.GAME_MODE = "blast"` (tap-to-blast clusters, Toon Blast style) is the shipped mode; classic swap Match-3 is still available through `config.BLAST_MODE` / the `pvp.blast_mode` config flag, and the board drag works in both. New profiles start with 3 moves (`START_MOVES`, cap 7) and switch to the x2 pace after their second win. `battle_view.lua` keeps the pace constants (`ANIM_FAST`, `STEP_DUR`, `AI_TURN_SPEED`, `HINT_DELAY`) together. Campaign stages from 4 have 2 waves; key bosses have 2–3 waves and the first boss (stage 6) offers a temporary relic before its final wave. Enemies scale from `campaign.expected_build(n)` (expected card level / moves / commander HP) with `M.BOSS_TUNE` per boss. Re-check with the headless simulation (`--screen=sim`) after changing `config`, `squads`, `campaign` or `battle`: stages 1–3 must stay 95–100%, bosses 35–65%, the stage after a boss is a valley.
11. **Poki SDK & Button Rules**: `gameplay_start` fires on the player's first tap and stays active through hub/tab management; `gameplay_stop` only for pause, commercial/rewarded breaks and hidden tabs. First `commercial_break` is before battle 5, then at most once every 3 battles (`poki.break_due`). All audio is muted during ads; `rewarded_break` buttons always have a non-rewarded alternative at least as prominent and are never green.
12. **Web economy timers**: chest unlock times must stay inside a ~10-minute Poki session (first earned chests 0s, wood 10s, silver 2m, royal 7m) and every victory cuts `config.CHEST_WIN_CUT` (45s) from the active chest; the Hub shows a short `-45s` toast on that slot.
13. **Localization & Assets**: Visible strings live in `main/modules/locales/<lang>.lua` (one table per language, `NAME` = native name) and are read through `main/modules/i18n.lua`. Ship the 10 Poki locales the bundled font can render: `en, es, pt, ru, tr, pl, de, fr, it, nl` (`i18n.LANGS`, in Poki priority order). The first-run language comes from `poki.language()` (`PokiSDK.getLanguage()` via `html5.run`), then the OS locale, then English; a manual choice in Settings overrides it and is saved in `progress.data.lang`. Every locale must have the same keys as `locales/en.lua` (the reference). Always regenerate `main/assets/fonts/main.font` (`node tools/gen_font.js`) and validate it (`node tools/check_fonts.js`: TTF glyph coverage, atlas contents, cache estimate, key parity), `main/assets/game.atlas` + `main/gui/sprite_sizes.lua` (`node tools/gen_sprites.js`), and `main/sounds.go` + WAVs + music loop (`node tools/gen_sounds.js`) instead of hand-editing generated files. CJK / Vietnamese / Arabic / Thai / Devanagari need glyphs Nunito-Black.ttf does not have, so those fall back to English (add a second font + Live Update before adding them). Lazy art (`bundle_resources/common/lazy`, generated by `gen_sprites.js`) is copied next to `index.html` by the bundler and fetched at runtime as `lazy/img/*.png`; that only works in web bundles, so the editor and native builds keep the atlas fallbacks (no HTTP errors). Use `--cfg=pvp.lazy_debug=1` in the smoke test to trace lazy loading.
14. **Testing**: `sh tools/build_web.sh` builds the web bundle; `node tools/web_smoke.js "bundle/web/GemVanguard" out --screen=<home|hub_early|cards|map|shop|quests|tower|battle|wave|boss_relic|pvp|chest|win|road|stage|trial|settings|language|sim> --lang=<en|es|pt|ru|tr|pl|de|fr|it|nl> --size=WxH [--steps=...]` takes screenshots in headless Edge/Chrome and counts Lua errors; `--cfg=pvp.poki_debug=1` traces the Poki lifecycle, `--cfg=pvp.autoplay=1` plays through the normal input path; `node tools/check_fonts.js` must pass before shipping.
